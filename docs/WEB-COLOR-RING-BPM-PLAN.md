# 网页播放器色环 BPM 变速开发计划

状态：待实施。设计基线为 `fix/obs-visual-progress-stability` 的 `4241583`。前端目标是外置 `color-player` 主题，后端目标是 FluentFlyout 的 WebSocket 服务。

## 目标与现状

让快歌带动色环转得更快，慢歌带动色环转得更慢。色环连续旋转，本期只估计速度，不要求某个颜色在鼓点到来时经过指定位置。

- 主题的 `scripts/color-picker.js` 使用帧间时间累加色相，当前速度为 24°/秒。`scripts/player.js` 通过布尔事件 `color-player-playback` 控制同步启停。
- [Visualizer.cs](../FluentFlyoutWPF/Classes/Visualizer.cs) 已有 WASAPI 输出设备回环采集和频谱分析。[任务栏控件](../FluentFlyoutWPF/Controls/TaskbarVisualizerControl.xaml.cs) 管理其启停。当前采集对象是整个输出设备的混音，SMTC 所选播放器与采集设备之间没有逐应用隔离。
- [WebSocket 协议](../FluentFlyoutWPF/Web/README.md) 已发布曲目与播放状态。BPM 作为可选扩展独立更新，进度条的时间线和校准逻辑不参与节奏估算。

## 阶段一 · 在主题中验证变速手感

- [ ] 增加独立的“按音乐 BPM 调速”选项，默认关闭。沿用现有播放同步开关决定是否旋转。保留手动选色、页面隐藏时暂停及恢复计时的行为。
- [ ] 以 120 BPM 对应 24°/秒为初始设计值，目标角速度为 `24 × BPM / 120`。复用同一动画循环和色相值，约一秒平滑过渡到目标转速。无有效 BPM 时使用 24°/秒。
- [ ] 用模拟的 80、120、160 BPM 输入验收。稳定后每圈应分别约为 22.5、15、11.25 秒。在 30 和 60 FPS 下检查圈时、切速时角度连续、暂停恢复无补转，以及色环、三角形与色块同步。此阶段可单独交付主题供 OBS 试用。

## 阶段二 · 共用音频采集并估算 BPM

- [ ] 从现有 Visualizer 提取采集生命周期。任务栏频谱和 BPM 分析按需使用同一设备流；最后一个使用者退出时释放设备。单独运行 BPM 时跳过任务栏位图绘制。
- [ ] 按实际音频格式解析完整声道帧，生成单声道分析信号，用帧数和采样率计时。在有界缓冲区中记录短时能量或频谱增长量，根据连续起音间隔估算 BPM。分析放在采集回调之外，记录估算置信度，并对半速、倍速候选作稳定性判断。
- [ ] 用已知 80、120、160 BPM 的节拍音在 44.1/48 kHz、单声道/立体声下验证。初步验收目标为稳定输入 10 秒后误差不超过 3 BPM。静音和无稳定节奏输入应报告未知。切换设备、休眠恢复或采集中断后应清空旧样本。另用真实音乐测首次稳定时间，记录误判后再定参数。

## 阶段三 · 通过 WebSocket 发布并接入主题

- [ ] 为当前媒体状态增加可空数值 `bpm`。仅在当前曲目取得可信估算时赋值。首次连接的 `state.snapshot` 和后续 `media.changed` 使用相同语义；BPM 稳定变化时主动发布，即使此时没有 SMTC 时间线事件。
- [ ] 在切歌、切换媒体会话或采集设备时递增分析代次，丢弃旧代次的异步结果。暂停时停止累计样本，恢复后重新建立估算。服务端合并重复更新，仅向网页发送估算结果。
- [ ] 主题读取可选字段，沿用布尔播放事件的既有含义。字段缺失、空值、无效值、断线或新曲目尚无估算时，清除旧目标并平滑回到默认转速。启停仍由播放同步开关控制。
- [ ] 验收旧主题连接新服务、新主题连接旧服务、连续切歌、暂停后换歌、断线重连及多个 OBS 浏览器源同时订阅。重点确认重连快照与当前曲目一致，同一设备只启动一次采集。

## 阶段四 · Windows 与 OBS 实机验收

- [ ] 在应用中提供 BPM 分析开关，默认关闭。在分析开启且有网页客户端需要服务时启动 BPM 采集，最后一个客户端退出后释放其采集需求。覆盖仅任务栏、仅 OBS、两者同时开启以及全部关闭。
- [ ] 用 Apple Music 和另一款 SMTC 播放器测试节奏稳定曲目、弱节奏前奏、静音、拖动进度和音频设备切换。加入通知音或游戏声验证混音干扰，记录估算偏差。此版本以音乐为设备主要声音作为适用条件。
- [ ] 在同一歌曲、设备和 OBS 场景下比较功能关闭与开启时的 CPU、内存和网页帧率。持续播放后多次切场景、重连并退出，检查采集器、缓冲区和动画循环能否释放。
- [ ] 完成 Windows CI、协议文档更新及外置主题包实机验证。交付时记录测得的首次稳定时间、误差、性能开销和已知限制。用户可分别关闭网页调速或应用端分析。

阶段一和阶段二可分别验证；阶段三在两者通过后联调，阶段四通过后发布。

## 阶段二实现记录

分支 `feature/shared-audio-bpm`。后台消费者可按需创建 `BpmCaptureSession`，读取可空的 `Current`（BPM、置信度），结束时等待 `DisposeAsync()`。任务栏频谱与分析器按设备 ID 共享 WASAPI 捕获，任务栏继续自行管理绘制和启停。阶段三负责从 WebSocket 服务创建该会话。

自动化用例位于 `FluentFlyoutWPF.Tests/TempoEstimatorTests.cs`。待实机记录真实音乐的首次稳定时间、半速或倍速误判，以及两种消费者交错启停、设备切换和休眠恢复的表现。
